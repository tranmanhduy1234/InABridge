========================================================
  PHÂN TÍCH RỦI RO CHIẾN LƯỢC & ĐỀ XUẤT
  VLM Custom — DINOv2-L + DeBERTa-V3 Q-Former + Qwen2.5-7B
  Dataset: 70M image-text pairs
  Compute: ~96GB VRAM (FSDP + ZeRO-2/3)
  Mục tiêu: nghiên cứu cá nhân, visual QA phức tạp
========================================================

  Phân loại rủi ro theo 3 chiều:
    [KT] = Kỹ thuật        — lỗi implementation, architecture
    [CL] = Chiến lược học  — model không học được gì có ý nghĩa
    [TN] = Tài nguyên      — compute, thời gian, memory

========================================================
  PHẦN 1 — RỦI RO MỨC ĐỘ NGHIÊM TRỌNG CAO
========================================================

────────────────────────────────────────────────────────
  [CL-1] DINOv2 + Q-Former: alignment cold-start problem
  Mức độ: NGHIÊM TRỌNG
────────────────────────────────────────────────────────
  Bản chất vấn đề:
    BLIP-2 gốc dùng CLIP/EVA-CLIP — visual encoder đã có
    ngầm định về "concept" liên quan đến ngôn ngữ từ
    contrastive pretraining. Q-Former chỉ cần học cách
    "hỏi đúng câu hỏi" để kéo thông tin đó ra.

    DINOv2 hoàn toàn không có điều này. Features của nó
    tối ưu cho spatial structure, texture, object boundary —
    không có bất kỳ signal nào về ngôn ngữ. Q-Former phải
    tự bootstrap alignment từ zero trên 70M pairs.

  Hệ quả cụ thể:
    - ITC loss sẽ giảm rất chậm ở 50k-200k steps đầu
    - Nguy cơ Q-Former học shortcut: align CLS token của
      DINOv2 (summary global) thay vì học từ patch tokens
      (spatial detail) — dẫn đến model giỏi captioning
      nhưng kém spatial QA
    - ITM hard negative mining sẽ kém hiệu quả ở giai đoạn
      đầu vì ITC chưa đủ tốt để mine hard negatives

  Đề xuất xử lý:
    A. Curriculum learning cho stage 1:
       - 0 → 10M steps: chỉ train ITC với in-batch negatives
         đơn giản, lr_qformer = 1e-4
       - 10M → 40M steps: thêm ITM, bắt đầu hard negative mining
       - 40M → 70M steps: thêm ITG, giảm lr xuống 5e-5

    B. Warm-start visual projection:
       - Trước khi train Q-Former, train riêng Linear(1024, 768)
         bằng cách align DINOv2 CLS token với DeBERTa [CLS]
         của caption tương ứng (simple contrastive, 1-2 epoch)
       - Giúp Q-Former có điểm khởi đầu tốt hơn

    C. Monitor metric:
       - Log ITC recall@1, recall@5 trên validation set
         mỗi 5k steps
       - Nếu R@1 < 0.3 sau 50k steps → dừng, review lr và
         negative sampling strategy

────────────────────────────────────────────────────────
  [KT-1] Disentangled attention silent failure
  Mức độ: NGHIÊM TRỌNG
────────────────────────────────────────────────────────
  Bản chất vấn đề:
    DeBERTa-V3 dùng disentangled attention với 2 loại vector:
      H_c: content vector (semantic)
      H_r: relative position vector
    Attention score = f(H_c_i, H_c_j) + f(H_c_i, H_r_ij)
                    + f(H_r_ij, H_c_j)

    Khi cross-attention attend to visual patch tokens:
      - Visual tokens không có relative position tự nhiên
      - H_r giữa query token và visual token sẽ là garbage
      - Attention score bị nhiễu bởi meaningless position term
      - Model có thể vẫn train và loss giảm nhưng cross-attention
        không học được spatial relationship đúng

  Đây là lỗi thầm lặng nguy hiểm nhất trong toàn bộ pipeline
  vì: loss vẫn giảm, model vẫn generate text, nhưng visual
  understanding không thực sự hoạt động.

  Đề xuất xử lý (theo thứ tự ưu tiên):
    Option A (khuyến nghị):
      Trong cross-attention layers, replace DeBERTa's
      disentangled attention bằng standard scaled dot-product:
        Attention(Q, K, V) = softmax(QK^T / sqrt(d)) V
      Chỉ giữ disentangled attention ở self-attention layers
      (nơi relative position giữa text tokens có ý nghĩa)

    Option B (đơn giản hơn):
      Set position_biases = 0 trong cross-attention
      (disable hoàn toàn position term, chỉ dùng content)

    Validation test bắt buộc trước khi train full:
      - Train 1k steps với 100 samples
      - Visualize cross-attention map: mỗi query token
        có attend đến các visual patch khác nhau không?
      - Nếu tất cả queries attend đến cùng một vài patches
        → position encoding đang interfere

────────────────────────────────────────────────────────
  [KT-2] ITG loss target token ID mismatch
  Mức độ: NGHIÊM TRỌNG
────────────────────────────────────────────────────────
  Bản chất vấn đề:
    ITG (Image-grounded Text Generation) ở stage 1:
      Input  : Q_out (visual queries) + text tokens
      Target : next token prediction trên DeBERTa vocab

    Stage 2 generation:
      Input  : Q_out (32 soft tokens) + instruction
      Target : next token prediction trên Qwen2.5 vocab

    Q-Former được train để extract visual info phục vụ
    predict DeBERTa tokens. Nhưng Qwen2.5 cần visual info
    phục vụ predict Qwen tokens. Đây là objective mismatch
    giữa hai stage.

  Mức độ nghiêm trọng thực tế:
    Trung bình — không fatal nhưng sẽ làm stage 2 cần
    nhiều data và steps hơn để compensate.
    Q_out vẫn chứa visual information hữu ích, chỉ là
    không được "định hướng" tốt cho Qwen generation.

  Đề xuất xử lý:
    Option A (giữ nguyên, chấp nhận trade-off):
      Stage 2 train lâu hơn ~20-30% so với dùng Qwen
      tokenizer xuyên suốt. Acceptable cho research.

    Option B (xử lý triệt để):
      Bỏ ITG loss ở stage 1, chỉ giữ ITC + ITM.
      ITG chỉ thực hiện ở stage 2 với Qwen vocab.
      Trade-off: Q-Former mất một objective quan trọng
      nhưng loại bỏ hoàn toàn tokenizer mismatch.

    Option C (tốt nhất nếu có thể):
      Stage 1 ITG: dùng Qwen2.5 tokenizer để tokenize
      caption, nhưng vẫn dùng DeBERTa embedding để encode.
      → Tức là: Qwen tokenizer → token IDs → DeBERTa
        embedding lookup → Q-Former → predict Qwen token IDs
      Cần thêm một embedding lookup table riêng.
      Phức tạp hơn nhưng loại bỏ mismatch hoàn toàn.

    Khuyến nghị cho research cá nhân: Option A hoặc B.

========================================================
  PHẦN 2 — RỦI RO MỨC ĐỘ TRUNG BÌNH
========================================================

────────────────────────────────────────────────────────
  [TN-1] Memory bottleneck với 70M pairs + FSDP
  Mức độ: TRUNG BÌNH
────────────────────────────────────────────────────────
  Ước tính memory stage 1 (per GPU, 96GB total):
    DINOv2-L frozen          :  ~1.2GB  (inference only)
    DeBERTa-V3 Q-Former      :  ~1.4GB  (train, fp16)
    Optimizer states (AdamW) :  ~2.8GB  (2× param size)
    Activations (B=64)       :  ~4-8GB  (tùy seq length)
    Visual projection        :  ~0.1GB
    ────────────────────────────────────────
    Tổng stage 1 ước tính    :  ~10-14GB per GPU

  Stage 1 hoàn toàn fit trong budget với ZeRO-2.
  ZeRO-3 không cần thiết cho stage 1.

  Ước tính memory stage 2:
    Qwen2.5-7B frozen        :  ~14GB   (fp16, inference)
    Qwen2.5-7B với LoRA      :  ~16GB   (thêm adapter)
    Q-Former + projection    :  ~2GB    (train)
    Optimizer states         :  ~4GB
    Activations (B=16-32)    :  ~8-16GB
    ────────────────────────────────────────
    Tổng stage 2 ước tính    :  ~44-48GB

  Stage 2 vẫn fit nhưng tight. Dùng ZeRO-2 là đủ.
  ZeRO-3 chỉ cần nếu muốn tăng batch size lớn hơn.

  Đề xuất cấu hình:
    Stage 1: FSDP + ZeRO-2, batch=128-256, grad_accum=4
    Stage 2: FSDP + ZeRO-2, batch=32-64,  grad_accum=8
    Precision: bf16 (Qwen2.5 pretrain bằng bf16, không dùng fp16)

────────────────────────────────────────────────────────
  [CL-2] 70M pairs: đủ về lượng nhưng chưa chắc về chất
  Mức độ: TRUNG BÌNH
────────────────────────────────────────────────────────
  BLIP-2 dùng 129M pairs (LAION + CC3M + CC12M + SBU).
  70M pairs là reasonable nếu data chất lượng tốt.

  Rủi ro cụ thể:
    - Nếu data chủ yếu là web-crawled captions (noisy):
      ITC sẽ plateau sớm vì nhiều false negatives
    - Nếu data thiếu diversity (chỉ 1-2 domain):
      Q-Former overfit domain, kém generalization

  Đề xuất:
    - Ưu tiên dùng: LAION-COCO (600M synthetic captions,
      lấy subset 50M), CC12M, CC3M, SBU, COCO captions
    - Filter bằng CLIP score > 0.25 trước khi train
      (loại ~30-40% noisy pairs)
    - Sau filter: ~40-50M high-quality pairs đủ tốt hơn
      70M noisy pairs

────────────────────────────────────────────────────────
  [KT-3] Qwen2.5-Instruct: frozen LLM bị template rigid
  Mức độ: TRUNG BÌNH
────────────────────────────────────────────────────────
  Qwen2.5-Instruct đã bị RLHF fine-tune với chat template
  cứng. Khi frozen hoàn toàn ở stage 2:
    - LLM expect input theo format nhất định
    - Visual soft tokens (32 vectors) là "ngoại lai"
      với distribution LLM đã thấy trong RLHF
    - Có thể dẫn đến: LLM generate đúng format nhưng
      ignore nội dung visual, hoặc generate repetitive output

  Đề xuất:
    - Stage 2a: Frozen Qwen, train Q-Former + projection
      với learning rate thấp (1e-5), 1-2 epoch
    - Stage 2b: Unfreeze Qwen với LoRA (rank=16, alpha=32)
      target: q_proj, v_proj, o_proj
      lr_lora = 2e-4, lr_qformer = 5e-5
    - Không unfreeze full Qwen — catastrophic forgetting
      và out-of-budget

────────────────────────────────────────────────────────
  [CL-3] Visual QA phức tạp: Q-Former 32 tokens có đủ?
  Mức độ: TRUNG BÌNH
────────────────────────────────────────────────────────
  BLIP-2 gốc dùng 32 query tokens.
  Với mục tiêu "trả lời câu hỏi phức tạp":
    - 32 tokens compress 257 visual tokens (DINOv2-L patch)
    - Compression ratio: 257 → 32 (~8x)
    - Với ảnh phức tạp (nhiều object, text trong ảnh,
      spatial relationship): 32 tokens có thể thiếu

  Đề xuất thử nghiệm:
    - Bắt đầu với 32 tokens (baseline)
    - Nếu model kém trên spatial QA và counting tasks:
      tăng lên 64 tokens, so sánh performance
    - Trade-off: 64 tokens → stage 2 input dài hơn,
      Qwen2.5 phải process thêm 32 tokens mỗi sample

========================================================
  PHẦN 3 — RỦI RO MỨC ĐỘ THẤP (ĐÃ CÓ HƯỚNG XỬ LÝ)
========================================================

  [KT-4] Dimension mismatch
    DINOv2 1024 → Q-Former 768 → Qwen 3584
    → Xử lý bằng Linear projection, không có rủi ro nếu
      init đúng (Kaiming hoặc Xavier uniform)

  [KT-5] DeBERTa embedding frozen vs Qwen tokenizer
    → Đã phân tích: gap được cách ly tốt qua Q_out vectors
    → Monitor: nếu ITG loss plateau sau 20k steps,
      thử unfreeze embedding với lr=1e-6

  [TN-2] Training time ước tính
    Stage 1 (70M pairs, batch=128, 1 epoch):
      ~545k steps × time_per_step
      Với 8×A100 40GB: ~3-5 ngày
      Với 4×A100 40GB: ~6-10 ngày
    Stage 2 (instruction tuning, ~1M samples):
      ~30k steps, ~1-2 ngày

========================================================
  PHẦN 4 — QUYẾT ĐỊNH KIẾN TRÚC CẦN CONFIRM TRƯỚC KHI CODE
========================================================

  Các quyết định sau ảnh hưởng đến toàn bộ codebase.
  Nên quyết định trước, không thay đổi giữa chừng.

  Q1. Cross-attention position encoding:
      [ ] Option A: Replace bằng standard attention
      [ ] Option B: Disable position bias = 0
      → Khuyến nghị: Option A

  Q2. ITG loss stage 1:
      [ ] Giữ nguyên (DeBERTa vocab target)
      [ ] Bỏ ITG stage 1, chỉ ITC + ITM
      [ ] Dùng Qwen tokenizer cho ITG target
      → Khuyến nghị: Bỏ ITG stage 1 nếu muốn clean,
        Giữ nguyên nếu muốn gần với BLIP-2 gốc nhất

  Q3. Số query tokens:
      [ ] 32 (như BLIP-2 gốc)
      [ ] 64 (cho complex VQA)
      → Khuyến nghị: Bắt đầu 32, ablate sau

  Q4. DeBERTa embedding trong stage 1:
      [ ] Frozen
      [ ] Trainable
      → Khuyến nghị: Frozen stage 1, optional unfreeze stage 2

  Q5. Stage 2 Qwen fine-tune:
      [ ] Full frozen
      [ ] LoRA (rank=16)
      [ ] LoRA (rank=32)
      → Khuyến nghị: LoRA rank=16 với 96GB budget

  Q6. Visual tokens dùng trong Q-Former:
      [ ] Chỉ patch tokens (256 tokens, bỏ CLS)
      [ ] CLS + patch tokens (257 tokens)
      [ ] Chỉ CLS token (1 token, rất compressed)
      → Khuyến nghị: 256 patch tokens (bỏ CLS),
        vì DINOv2 CLS ít spatial detail hơn patch tokens

========================================================
  PHẦN 5 — CHIẾN LƯỢC THỰC NGHIỆM ĐỀ XUẤT
========================================================

  Với mục tiêu nghiên cứu cá nhân, không cần đạt SOTA.
  Cần: pipeline chạy được, model hiểu visual, có thể ablate.

  PHASE 0 — Sanity check (1-2 ngày, không tốn GPU lớn):
    [ ] Train 1k steps trên 10k samples
    [ ] Kiểm tra ITC loss giảm (không plateau ngay)
    [ ] Visualize cross-attention map (xem KT-1 diagnosis)
    [ ] Kiểm tra Qwen nhận visual tokens đúng vị trí
    Nếu cả 3 pass → proceed to Phase 1

  PHASE 1 — Stage 1 mini (3-5 ngày):
    [ ] Train trên 5M pairs (7% data), 1 epoch
    [ ] Eval ITC R@1, R@5 trên COCO val
    [ ] Target: R@1 > 0.4 (BLIP-2 với CLIP đạt ~0.65,
        DINOv2 cold-start kỳ vọng thấp hơn)
    Nếu đạt → train full 70M
    Nếu không đạt → review curriculum learning (CL-1)

  PHASE 2 — Stage 1 full (5-10 ngày):
    [ ] Train 70M pairs, 1 epoch
    [ ] Checkpoint mỗi 50k steps
    [ ] Eval COCO captioning (CIDEr score) để track progress

  PHASE 3 — Stage 2 (2-3 ngày):
    [ ] Instruction tuning với LLaVA-Instruct 150K
        + VQAv2 train + GQA train
    [ ] Eval: VQAv2 test-dev, GQA test-balanced

  PHASE 4 — Ablation (tuỳ):
    [ ] So sánh 32 vs 64 query tokens
    [ ] So sánh có/không có ITG stage 1
    [ ] So sánh DINOv2 vs CLIP backbone (nếu có thời gian)
